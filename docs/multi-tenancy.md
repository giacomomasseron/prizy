## Overview

Prizy uses a **single-database multi-tenancy** model. Every organisation is a **Workspace** (tenant). All tenant-scoped tables carry a `workspace_id UUID NOT NULL` foreign key that references `workspaces(id)`.

The `spatie/laravel-multitenancy` package is responsible for:

- Resolving the active tenant from each incoming HTTP request (subdomain or custom domain).
- Storing the current `Workspace` in a singleton (`CurrentTenant`) so it is accessible anywhere in the request lifecycle.
- Executing a configurable list of **Tasks** each time the tenant is switched (e.g., setting a global scope, binding the workspace ID into the IoC container).
- Propagating the current tenant to queued jobs automatically.

No separate database connections or schema switches are used — isolation is enforced entirely through `workspace_id` filtering at the application layer, backed by PostgreSQL row-level policies and the `WorkspaceScope` global scope.

## Installation

```bash
composer require spatie/laravel-multitenancy
php artisan vendor:publish --provider="Spatie\Multitenancy\MultitenancyServiceProvider" --tag="multitenancy-config"
php artisan vendor:publish --provider="Spatie\Multitenancy\MultitenancyServiceProvider" --tag="multitenancy-migrations"
```

> The published migration creates a `landlord` connection and a `tenants` table. **Discard that migration** — Prizy already has `workspaces` as the tenant table (see `schema.sql`). The `landlord` connection concept does not apply to single-database tenancy; all connections point to the same PostgreSQL database.

## Configuration

`config/multitenancy.php`:

```php
return [

    /*
     * The model used as the Tenant. Must extend Spatie\Multitenancy\Models\Tenant.
     */
    'tenant_model' => \App\Models\Workspace::class,

    /*
     * Column on the tenants table used to match the domain/subdomain.
     * Prizy resolves by slug (subdomain) or custom_domain.
     */
    'tenant_finder' => \App\Multitenancy\WorkspaceTenantFinder::class,

    /*
     * Tasks executed for tenant switching. spatie/laravel-multitenancy v4 builds
     * ONE task collection from this key and runs each task's makeCurrent() when a
     * tenant is set and forgetCurrent() when it is forgotten (end of request).
     * There is no separate forget_current_tenant_tasks key in v4 — the unset logic
     * lives in SetWorkspaceScopeTask::forgetCurrent() below.
     */
    'switch_tenant_tasks' => [
        \App\Multitenancy\Tasks\SetWorkspaceScopeTask::class,
        \App\Multitenancy\Tasks\BindWorkspaceToContainerTask::class,
    ],

    /*
     * Whether queued jobs should automatically carry the current tenant.
     */
    'queues_are_tenant_aware_by_default' => true,

];
```

## Tenant Model — Workspace

`App\Models\Workspace` (generated by `laravel-models-generator`, extended for tenancy):

```php
<?php

declare(strict_types=1);

namespace App\Models;

use Spatie\Multitenancy\Models\Tenant;
use Illuminate\Database\Eloquent\Factories\HasFactory;
use Illuminate\Database\Eloquent\SoftDeletes;

/**
 * The Workspace is the root aggregate for a tenant.
 * Extending Spatie's Tenant makes it the CurrentTenant target.
 *
 * @property string      $id
 * @property string      $name
 * @property string      $slug          — used as subdomain (e.g. acme → acme.app.com)
 * @property string|null $custom_domain — optional CNAME
 * @property string|null $logo_url      — workspace logo URL
 * @property string      $plan
 * @property string      $timezone
 * @property string      $locale
 */
final class Workspace extends Tenant
{
    use HasFactory;
    use SoftDeletes;

    protected $table = 'workspaces';
    protected $primaryKey = 'id';
    public    $incrementing = false;
    protected $keyType = 'string';

    protected $fillable = [
        'name',
        'slug',
        'custom_domain',
        'logo_url',
        'plan',
        'timezone',
        'locale',
    ];

    protected $casts = [
        'created_at' => 'datetime',
        'updated_at' => 'datetime',
        'deleted_at' => 'datetime',
    ];

    // -----------------------------------------------------------------
    // Relationships
    // -----------------------------------------------------------------

    public function users(): \Illuminate\Database\Eloquent\Relations\HasMany
    {
        return $this->hasMany(User::class, 'workspace_id');
    }

    public function teams(): \Illuminate\Database\Eloquent\Relations\HasMany
    {
        return $this->hasMany(Team::class, 'workspace_id');
    }
}
```

> **Note:** `spatie/laravel-multitenancy` reads the tenant key via `getTenantKey()` which returns `$this->getKey()` — the UUID primary key.

## Tenant Resolution

Prizy resolves the active workspace from every request by inspecting either:

1. **Subdomain** — `acme.app.com` → `slug = 'acme'`
2. **Custom domain** — `support.acme.com` → `custom_domain = 'support.acme.com'`

`App\Multitenancy\WorkspaceTenantFinder`:

```php
<?php

declare(strict_types=1);

namespace App\Multitenancy;

use Illuminate\Http\Request;
use Illuminate\Support\Str;
use Spatie\Multitenancy\Contracts\IsTenant;
use Spatie\Multitenancy\TenantFinder\TenantFinder;
use App\Models\Workspace;

final class WorkspaceTenantFinder extends TenantFinder
{
    public function findForRequest(Request $request): ?IsTenant
    {
        $host = $request->getHost(); // e.g. "acme.app.com" or "support.acme.com"

        // 1. Try custom domain first (exact match).
        $workspace = Workspace::query()
            ->where('custom_domain', $host)
            ->first();

        if ($workspace) {
            return $workspace;
        }

        // 2. Fall back to subdomain slug (strip the base domain).
        // Base domain is derived from APP_BASE_DOMAIN, e.g. "app.com".
        $baseDomain = config('app.base_domain'); // e.g. "app.com"
        $subdomain  = Str::before($host, '.' . $baseDomain);

        if ($subdomain === $host) {
            // No subdomain detected — host IS the base domain (landing page, API, etc.)
            return null;
        }

        return Workspace::query()
            ->where('slug', $subdomain)
            ->first();
    }
}
```

Add `APP_BASE_DOMAIN=app.com` to `.env`.

## Tenant Tasks

Tasks are plain classes that implement `Spatie\Multitenancy\Tasks\SwitchTenantTask`. They run in sequence every time `Tenant::makeCurrent()` is called.

### SetWorkspaceScopeTask

Registers the `WorkspaceScope` global scope with the current `workspace_id` on every tenant-aware model. It also publishes the tenant id to the PostgreSQL session (`app.current_workspace_id`) so the Row-Level Security policies in `schema.sql` SECTION 7 engage as a database-level backstop.

```php
<?php

declare(strict_types=1);

namespace App\Multitenancy\Tasks;

use Illuminate\Support\Facades\DB;
use Spatie\Multitenancy\Contracts\IsTenant;
use Spatie\Multitenancy\Tasks\SwitchTenantTask;
use App\Scopes\WorkspaceScope;

final class SetWorkspaceScopeTask implements SwitchTenantTask
{
    public function makeCurrent(IsTenant $tenant): void
    {
        WorkspaceScope::setCurrentWorkspaceId($tenant->getKey());

        // Expose the tenant to PostgreSQL RLS (schema.sql SECTION 7):
        // policies read current_setting('app.current_workspace_id').
        DB::statement(
            "SELECT set_config('app.current_workspace_id', ?, false)",
            [$tenant->getKey()]
        );
    }

    public function forgetCurrent(): void
    {
        WorkspaceScope::clearCurrentWorkspaceId();

        // Clear the GUC so landlord / cross-tenant work runs unscoped
        // (RLS is permissive when the setting is empty).
        DB::statement("SELECT set_config('app.current_workspace_id', '', false)");
    }
}
```

### BindWorkspaceToContainerTask

Binds the current `Workspace` into Laravel's service container so any class can `app(Workspace::class)` to retrieve it without reaching through `CurrentTenant`.

```php
<?php

declare(strict_types=1);

namespace App\Multitenancy\Tasks;

use Spatie\Multitenancy\Contracts\IsTenant;
use Spatie\Multitenancy\Tasks\SwitchTenantTask;
use App\Models\Workspace;

final class BindWorkspaceToContainerTask implements SwitchTenantTask
{
    public function makeCurrent(IsTenant $tenant): void
    {
        app()->instance(Workspace::class, $tenant);
    }

    public function forgetCurrent(): void
    {
        app()->forgetInstance(Workspace::class);
    }
}
```

> **Teardown:** there is no separate "unset" task. spatie v4 runs each
> `switch_tenant_tasks` entry's `forgetCurrent()` when the tenant is forgotten,
> so `SetWorkspaceScopeTask::forgetCurrent()` (above) is what clears the
> `WorkspaceScope` static and resets the `app.current_workspace_id` GUC.

## Model Integration — TenantAwareEntity

Every tenant-scoped Entity extends the hand-maintained `TenantAwareEntity` base, which applies the custom `WorkspaceScope` global scope and auto-populates `workspace_id` on `create`.

> **Note:** `spatie/laravel-multitenancy` ships **no** column-scoping model trait. Its model concerns (`Spatie\Multitenancy\Models\Concerns\UsesTenantConnection`, `UsesLandlordConnection`, `ImplementsTenant`) target the *multi-database* strategy. For Prizy's single-database, `workspace_id`-column strategy, scoping is done entirely by our own `WorkspaceScope` and the `creating` hook below — there is no package trait to apply.

```php
<?php

declare(strict_types=1);

namespace App\Models;

use Illuminate\Database\Eloquent\Factories\HasFactory;
use Illuminate\Database\Eloquent\Model;
use Illuminate\Database\Eloquent\SoftDeletes;
use App\Scopes\WorkspaceScope;

/**
 * Base entity for all tenant-scoped Eloquent models.
 * Generated by laravel-models-generator; this base class is hand-maintained.
 */
abstract class TenantAwareEntity extends Model
{
    use HasFactory;

    /**
     * Every Prizy tenant table uses a UUID primary key (DEFAULT gen_random_uuid()),
     * so the key is a non-incrementing string. Generated subclasses also carry a
     * #[Table(keyType: 'string', incrementing: false)] attribute; these properties
     * make the base class authoritative for any hand-written tenant entity.
     */
    public $incrementing = false;

    protected $keyType = 'string';

    protected static function booted(): void
    {
        // Apply the global WorkspaceScope to every subclass automatically.
        static::addGlobalScope(new WorkspaceScope());

        // Auto-fill workspace_id on model creation.
        static::creating(function (self $model): void {
            if (empty($model->workspace_id)) {
                $model->workspace_id = WorkspaceScope::getCurrentWorkspaceId();
            }
        });
    }

    public function workspace(): \Illuminate\Database\Eloquent\Relations\BelongsTo
    {
        return $this->belongsTo(Workspace::class, 'workspace_id');
    }
}
```

All tenant-scoped entities generated by `laravel-models-generator` extend `TenantAwareEntity` instead of `Illuminate\Database\Eloquent\Model`. Example:

```php
// app/Models/Issue.php  (generated, excerpt)

final class Issue extends TenantAwareEntity
{
    // workspace_id is automatically scoped & filled by TenantAwareEntity
}
```

## WorkspaceScope Global Scope

`App\Scopes\WorkspaceScope`:

```php
<?php

declare(strict_types=1);

namespace App\Scopes;

use Illuminate\Database\Eloquent\Builder;
use Illuminate\Database\Eloquent\Model;
use Illuminate\Database\Eloquent\Scope;
use RuntimeException;

final class WorkspaceScope implements Scope
{
    /**
     * The workspace_id for the currently active tenant.
     * Set by SetWorkspaceScopeTask; cleared at end of request.
     */
    private static ?string $currentWorkspaceId = null;

    // ------------------------------------------------------------------
    // Static helpers (called by Tasks)
    // ------------------------------------------------------------------

    public static function setCurrentWorkspaceId(string $workspaceId): void
    {
        self::$currentWorkspaceId = $workspaceId;
    }

    public static function clearCurrentWorkspaceId(): void
    {
        self::$currentWorkspaceId = null;
    }

    public static function getCurrentWorkspaceId(): string
    {
        if (self::$currentWorkspaceId === null) {
            throw new RuntimeException('No active tenant. WorkspaceScope has not been initialised.');
        }

        return self::$currentWorkspaceId;
    }

    public static function hasCurrentWorkspace(): bool
    {
        return self::$currentWorkspaceId !== null;
    }

    // ------------------------------------------------------------------
    // Eloquent Scope contract
    // ------------------------------------------------------------------

    public function apply(Builder $builder, Model $model): void
    {
        if (self::$currentWorkspaceId !== null) {
            $builder->where(
                $model->getTable() . '.workspace_id',
                self::$currentWorkspaceId
            );
        }
    }
}
```

> The scope is intentionally **permissive when no tenant is active** (e.g. during artisan commands or Horizon workers that operate across all workspaces). Any cross-tenant operation that must be tenant-aware must call `Workspace::makeCurrent()` explicitly.

## Integration with Clean Architecture

### Repository Layer

All Repositories receive the current `workspace_id` through the `WorkspaceScope` (already applied by the global scope on every Entity). They **never** pass `workspace_id` as a parameter — it is implicit.

```php
<?php

declare(strict_types=1);

namespace App\Repositories;

use App\Models\Issue;
use GiacomoMasseroni\PHPCleanArchitecture\Contracts\RepositoryInterface;

final class IssueRepository implements RepositoryInterface
{
    /**
     * Returns issues for the CURRENT workspace only.
     * WorkspaceScope is applied automatically by TenantAwareEntity.
     */
    public function findOpenByTeam(string $teamId): \Illuminate\Database\Eloquent\Collection
    {
        return Issue::query()
            ->where('team_id', $teamId)
            ->whereNotIn('status', ['done', 'cancelled'])
            ->get();
    }

    public function create(\App\DataTransferObjects\Tracker\CreateIssueData $data): Issue
    {
        // workspace_id is auto-populated by TenantAwareEntity::creating() hook.
        return Issue::query()->create((array) $data);
    }
}
```

### UseCase Layer

UseCases access the current workspace via the container binding set by `BindWorkspaceToContainerTask`:

```php
<?php

declare(strict_types=1);

namespace App\UseCases\Workspace;

use App\Models\Workspace;
use App\DataTransferObjects\Workspace\UpdateWorkspaceSettingsData;
use App\Repositories\WorkspaceRepository;
use GiacomoMasseroni\PHPCleanArchitecture\BaseUseCase;
use GiacomoMasseroni\PHPCleanArchitecture\Contracts\UseCaseInterface;

final class UpdateWorkspaceSettingsUseCase extends BaseUseCase implements UseCaseInterface
{
    public function __construct(
        private readonly WorkspaceRepository $workspaceRepository,
        private readonly Workspace $workspace, // injected by BindWorkspaceToContainerTask
    ) {}

    public function handle(UpdateWorkspaceSettingsData $data): Workspace
    {
        return $this->workspaceRepository->update($this->workspace, $data);
    }
}
```

### Controller Layer

Controllers are thin — they only verify the tenant was resolved (the middleware handles this):

```php
<?php

declare(strict_types=1);

namespace App\Http\Controllers\Workspace;

use App\Http\Requests\Workspace\UpdateWorkspaceSettingsRequest;
use App\Http\Resources\WorkspaceResource;
use App\UseCases\Workspace\UpdateWorkspaceSettingsUseCase;
use GiacomoMasseroni\PHPCleanArchitecture\Contracts\ControllerInterface;
use Illuminate\Http\JsonResponse;

final class WorkspaceController implements ControllerInterface
{
    public function update(UpdateWorkspaceSettingsRequest $request): JsonResponse
    {
        $workspace = UpdateWorkspaceSettingsUseCase::actingAs($request->user())
            ->run($request->toData());

        return WorkspaceResource::make($workspace)->response();
    }
}
```

## Middleware

Register the Spatie `NeedsTenant` and `EnsureValidTenantSession` middleware in `bootstrap/app.php` (Laravel 13 style):

```php
use Spatie\Multitenancy\Http\Middleware\NeedsTenant;
use Spatie\Multitenancy\Http\Middleware\EnsureValidTenantSession;

->withMiddleware(function (Middleware $middleware): void {

    // Resolves the tenant and calls makeCurrent() for every API/web request.
    // Returns 404 if no tenant can be resolved (unknown subdomain/domain).
    $middleware->alias([
        'tenant'         => NeedsTenant::class,
        'tenant.session' => EnsureValidTenantSession::class,
    ]);

    // Apply to the entire "api" and "web" groups (all routes require a tenant).
    $middleware->appendToGroup('api', NeedsTenant::class);
    $middleware->appendToGroup('web', NeedsTenant::class);
})
```

Routes that must NOT require a tenant (landing page, sign-up, health-check) are registered **without** the tenant middleware:

```php
// routes/web.php — public / landlord routes
Route::withoutMiddleware(NeedsTenant::class)->group(function (): void {
    Route::get('/', LandingController::class);
    Route::post('/workspaces', CreateWorkspaceController::class);
    Route::get('/health', HealthController::class);
});
```

## Tenant-Aware Queued Jobs

With `queues_are_tenant_aware_by_default => true` in `config/multitenancy.php`, Spatie automatically serialises the current tenant key into every queued job payload and calls `Workspace::makeCurrent()` before the job is handled.

This means all Repositories, Entities, and Services inside a job operate under the correct `workspace_id` scope — no manual wiring is required.

For jobs that intentionally run **across all tenants** (e.g. a platform-wide health report), implement `Spatie\Multitenancy\Jobs\NotTenantAware`:

```php
use Spatie\Multitenancy\Jobs\NotTenantAware;

final class GeneratePlatformReportJob implements ShouldQueue, NotTenantAware
{
    public function handle(): void
    {
        // No workspace_id scope applied — queries touch all tenants.
        Workspace::all()->each(function (Workspace $workspace): void {
            $workspace->makeCurrent();
            // ... per-tenant work
            $workspace->forgetCurrent();
        });
    }
}
```

## Testing

### Setting up a tenant in tests

```php
use App\Models\Workspace;
use App\Scopes\WorkspaceScope;

// In a test base class or trait:
protected function setUpTenant(): Workspace
{
    $workspace = Workspace::factory()->create();
    $workspace->makeCurrent(); // triggers all Tasks → sets WorkspaceScope

    return $workspace;
}

protected function tearDown(): void
{
    Workspace::forgetCurrent();
    parent::tearDown();
}
```

### Example UseCase test

```php
use Tests\TestCase;
use App\Models\Workspace;
use App\Models\User;
use App\UseCases\Tracker\Issue\CreateIssueUseCase;
use App\DataTransferObjects\Tracker\CreateIssueData;

final class CreateIssueUseCaseTest extends TestCase
{
    public function test_creates_issue_scoped_to_current_workspace(): void
    {
        $workspace = $this->setUpTenant();
        $user      = User::factory()->for($workspace, 'workspace')->create();

        $data = new CreateIssueData(
            title:    'Fix login bug',
            teamId:   Team::factory()->for($workspace, 'workspace')->create()->id,
            priority: 'high',
        );

        $issue = CreateIssueUseCase::actingAs($user)->run($data);

        $this->assertSame($workspace->id, $issue->workspace_id);
        $this->assertDatabaseHas('issues', [
            'id'           => $issue->id,
            'workspace_id' => $workspace->id,
        ]);
    }

    public function test_cannot_read_issues_from_another_workspace(): void
    {
        $workspaceA = Workspace::factory()->create();
        $workspaceB = Workspace::factory()->create();

        $workspaceA->makeCurrent();
        $issueA = \App\Models\Issue::factory()->for($workspaceA, 'workspace')->create();
        $issueB = \App\Models\Issue::factory()->for($workspaceB, 'workspace')->create();

        // WorkspaceScope must filter out issueB
        $this->assertCount(1, \App\Models\Issue::all());
        $this->assertSame($issueA->id, \App\Models\Issue::first()->id);
    }
}
```

## Security Checklist

| Layer | Control | How |
|---|---|---|
| **HTTP** | Tenant resolved from host before any controller runs | `NeedsTenant` middleware |
| **Eloquent** | All queries automatically scoped to `workspace_id` | `WorkspaceScope` global scope on `TenantAwareEntity` |
| **Create** | `workspace_id` auto-filled from active tenant | `TenantAwareEntity::booted()` creating hook |
| **Policies** | Every Policy verifies `$user->workspace_id === $model->workspace_id` | Laravel Policies |
| **Database** | Row-Level Security on every `workspace_id` table as a last-resort backstop | PostgreSQL RLS policies (`schema.sql` SECTION 7), driven by the `app.current_workspace_id` session var set in `SetWorkspaceScopeTask` |
| **Queue** | Jobs carry and restore the correct tenant | Spatie tenant-aware queue serialisation |
| **Artisan** | Commands that fan-out across tenants iterate `Workspace::all()` and call `makeCurrent()` per tenant | Convention; enforced via code review |
| **Cross-tenant leakage** | `withoutGlobalScope(WorkspaceScope::class)` is banned in tenant-scoped Repositories | Deptrac custom rule (planned) |
